# Mosfeteer — working context

Mosfeteer: programmatic/agent-assisted schematic editor. Connectivity-based model rendered to SVG.
Repository: private `ojarvin/mosfeteer`.
Push over HTTPS only: SSH is unavailable headlessly; `origin` is HTTPS and `gh` is the credential helper.

## Visual and symbol rules

All symbols use the classic textbook look: filled gate bars, arrowheads, and power slabs are `polygon` graphics with `fill:'foreground'`; symbol linework uses butt caps and miter joins. `defineSymbol` marks an open absolute `symbol` path that starts or ends on a terminal as `terminalLead`. `svgString` draws every non-ghost solid wire and these leads (world coordinates, one shared miter limit of 5) as a single square-capped `wire-ink` path per stroke style in the wire layer, so overlaps at terminals are rasterized once instead of doubling anti-aliased edges into thicker joints; leads are pulled in by half the stroke width so the projecting cap ends exactly where the butt-ended lead did, and a wire meeting a lead at a right angle fills the corner. Per-segment `wire-*` elements remain unpainted (`stroke-opacity="0"`) hit and keyboard targets; ghost or dashed strokes keep their own elements. `style.js` keeps one internal stroke-role table: `symbol` (normal, butt), `wire` (square projecting caps, miter joins), `annotation` (round caps for visual lines/arrows and block-diagram connectors), `emph` (9.6), `ground` (11.6), `supply` (7.2), and the legacy `line` / `thick` fallbacks; `strokeAttrs`/`styleAttrs`/`fontAttrs`/`escapeSvg` are its public surface. SVG defaults to bottom annotations, middle wires, and top components/labels; `drawOrder` only restacks objects within their category. `fontAttrs('instance'|'label')` is unchanged.

Labels support `_{...}` markup, such as `C_{GS}`. Component names and their owned instance labels are one synchronized, unique identity for every symbol with an instance label, interface ports included and without exception: default numeric names persist explicit textbook markup (`M_{1}`) while the connectivity id remains `M1`; interface voltage ports default to `VI1`/`VO1`/`VIO1` and render as `V_{I1}`/`V_{O1}`/`V_{IO1}`; there is no implicit trailing-number subscript. Rename fields and labels accept markup such as `M_{2}` or `R_{D}`, canonicalize it for connectivity, and reject duplicates without mutating the circuit. A port additionally NAMES its physical net (`model.js` `_syncInterfacePinLabels`): while it is the only interface pin on that net, the net name and the port identity are one thing, so the net follows the port's authored label source (`V_{IN}`, refdes `VIN`) and renaming the net renames the port back (`_adoptNetNameAsPortIdentity`). Two ports therefore can never carry one name -- the collision is the ordinary component-name collision, and a virtual connection is made by naming the NET instead. Several ports on one net keep their own identities and the net keeps one name; a net name that cannot be a component identity (not a valid refdes, or already taken) also stays on the net alone, and that port's label keeps showing its own identity. Reference-marker child labels retain their specialized local-rail semantics. Alignment, anchors, and the bbox model are unchanged; `textWidth` scales explicit sub/superscript runs by ×0.62.

The resistor zigzag is centered and 180° symmetric; its path uses a miter limit of 5 to keep sharp corners visible. Capacitor plates are at x -12.94 and 12.94; the inductor coil spans x -58.49..58.49, centered on the origin. Diode uses the same centered footprint and terminals.
- **nmos, pmos**: `g`(-120,0), `d`(0,-80), `s`(0,80); bbox `{-120,-80,120,160}`. The gate has two filled bars at x -87.2..-75.6 and -66.3..-54.6. NMOS source arrow points out; PMOS source arrow points into the channel. PMOS has `defaultMirrorY:true`, placing its source up. Drain and source leads end exactly at their terminal coordinates and join wires inside the shared ink path (no seam patches are drawn). **nmosb, pmosb** add `b`(0,0), `dir:{x:1,y:0}`, and `direction:'bulk'`; an internal symbol-style path starts inside the channel bar at x=-56.98 (like the drain and source stubs, so no butt end meets the bar edge) and runs to the bulk terminal with the same terminal-coordinate endpoint. PMOS bulk retains `defaultMirrorY:true`. Their bulk label offset is `{40,-40}` (one grid cell toward local drain); plain MOS labels remain `{40,0}`.
- **npn, pnp**: `b`(-160,0), `c`(0,-120), `e`(0,120); PNP has collector bottom and emitter top. Filled emitter arrow, `emph` base bar, bbox `{-160,-120,160,240}`, and label at `{40,0}` on the right.
- **ground**: `gnd`(0,0), stub to y40, three `ground`-width bars at y 40/63.26/84.19, bbox `{0,0,80,120}`. **supply**: `p`(0,0), filled slab above, bbox `{-40,-80,80,80}`.
- **vcm**: `vcm`(0,0), upward-escaping terminal, downward stub to y24, open outline-only downward triangle from y24 to y56 (56 wide, 32 deep), bbox `{-40,0,80,80}`. No instance label; normal `symbol` stroke.
- **current_source, voltage_source**: `a`(0,-80), `b`(0,80), circle radius 35 with leads from ±35, bbox `{-40,-80,80,160}`, label center offset `{-80,0}` so a one-square default label's bbox edge is 40 units left of the origin. Current source has a filled downward arrow; voltage source has ± marks. Ref prefixes `I` and `V`. **vccs** shares that footprint with a closed 80×80 diamond body (`M 0 -40 L 40 0 L 0 40 L -40 0 Z`) and the same downward arrow, ref prefix `G`: the controlling voltage is its label (`g_{m1}(V_{IN} - 0)`), never a drawn control pair, which is why a hybrid-π figure stays readable.
- **opamp**: `ip`(-200,40), `im`(-200,-40), `o`(160,0). **opamp_diff** adds `op`(160,-40) and `om`(160,40); both use bbox `{-200,-120,360,240}` and ref prefix `U`. Differential output leads leave the slanted edges at x≈12.8/12.81 and run to x=160. All polarity marks are 28 units, centered at y=±40: input −/+ at x≈-76; output is flipped +/− at x≈-38 (`op` top, `om` bottom), clear of the body. Plain opamp input marks use the same rows.
- **inverter, buffer**: `a`(-120,0), `y`(120 or 80,0).
- **and, or, nand, nor**: `a`(-120,-40), `b`(-120,40), `y`(120,0). **xor, xnor** use `y`(160,0). Logic ref prefix is `U`. Every body is one continuous closed path (`Z`). AND/NAND top edge meets the curved front without a seam. OR/NOR concave backs shift left by -8 to overlap input lead tips ending at x=-76.88. XOR/XNOR shift the body and extra input-side line left by -22 together; that line lands on wire tips at x≈-77, and wires stop there rather than entering the gap between curves. Output lead and negation bubble shift with the body. Buffer/inverter triangles are closed with `Z` for a sharp miter; the inverter apex is hidden by its bubble.
- **adc, dac**: `emph` outline. ADC has a pointed analog-input side and flat digital-output side; DAC is reversed. ADC terminals `ain`(-200,0), `d`(200,0); DAC terminals `d`(-200,0), `aout`(200,0). A short diagonal slash crosses the digital lead. Centered upright label-font text says `ADC` or `DAC`; bbox `{-200,-120,400,240}`.
- **solder**: annotation dot only, radius `SOLDER_DOT_RADIUS=12`, exact bbox `{-12,-12,24,24}`. It is selected at its junction grid point, not as a grid cell. Placing one where at least three wire arms meet (a crossing, or a wire end on another wire) shorts those nets there through `Circuit#shortNetsAt(point,{name})` (joining any fixed net keeps the result fixed and literal, like `attachWireEndpoint`): auto-named nets keep the first net, one given name wins, and several given names throw `code:'net-name-choice'` so the editor opens a "Keep net name" picker beside the dot. Escape or an outside click cancels the whole placement (the dot is removed). A dot where fewer than three arms meet remains a plain annotation and is pruned by `syncJunctionSolders`. Terminal-less annotations are exempt from `validateSymbol`'s bbox-on-grid rule and from routing-environment and `evaluate()` overlap checks.
- **block**: schematic block shell with default bbox `{-80,-80,160,160}` and twelve generic perimeter terminals `T1`…`T12` (every non-corner grid slot on each side, including the four edge midpoints). It uses ordinary schematic wires, renders a centered bold/italic value (default `Block`) edited by double-clicking the body or its side-panel row, participates in overlap/body geometry, and its unused terminals are exempt from dangling-terminal diagnostics. Selected blocks expose the same eight resize handles as block-diagram nodes; resizing preserves connected terminal identities, regenerates unused perimeter slots, reroutes touched managed nets, and persists the per-instance size.
- **port**: textbook open-circle marker, terminal `p`(0,0), circle left of the lead, ref prefix `P`, owned label `P_{1}` at label offset `{-120,0}`. It is an interface pin (`model.js` `INTERFACE_PIN_TYPES`) exactly like the boxed ports: double-click edits its label, which is both its identity and the name of the net it names. The filled variant was removed; `fromJSON` loads legacy `port_filled` as `port` and gives unlabelled ports their owned label. **input, output, inputoutput**: boxed textbook ports with ref prefixes `VI`, `VO`, `VIO`, owned voltage labels `V_{I1}`, `V_{O1}`, `V_{IO1}` to the left at label offset `{-120,0}`. `output` has `defaultMirrorX:true`, putting its terminal on the circuit side and its box/arrow outward; the label offset mirrors with the symbol.
- **variable_resistor, variable_capacitor, variable_inductor**: composed at load time from the plain symbol definitions (`[...base.graphics, ...ADJUST]` in `variable.js`) so body geometry tracks the base. Adjustment arrow is a 45° shaft `M -48 48 L 36 -36` with filled head tip at (48,-48).

Label offsets: nmos/pmos `{40,0}`; nmosb/pmosb bulk labels `{40,-40}`; npn/pnp `{40,0}`; resistor/variable/capacitor/inductor/diode `{0,80}`; switch `{0,40}`; sources `{-80,0}`; ports `{-120,0}`; logic/opamps below the body.

`ComponentInstance` applies `defaultMirrorX/Y` only when the corresponding `opts.mirror*` is `undefined`. The CLI `add` command omits mirror flags unless explicitly passed, so symbol defaults apply everywhere.

## Labels, selection, and transforms

Labels are not symbols or components. They live in `circuit.labels: Map<id, LabelInstance>` and provide no connectivity. A `LabelInstance` has exactly one role:

1. owned instance label: `owner` is a component refdes and `offset` is local;
2. persistent electrical net label: `netId` identifies one physical net; or
3. free annotation: `owner:null`, `netId:null`, independent text and anchor.

A `netId` identifies one physical net and its drawable geometry. Nets with the same canonical name are virtual electrical connections for naming and analysis even when no wire joins their geometry; the physical net IDs remain separate so each drawable route and label occurrence stays intact. Small-signal analysis honours that: `analysis/context.js` `virtualNetAliases` maps every later member of a name group onto the first (case-sensitive, like `Circuit#logicallyConnected` and the net list's own grouping) through `nodeAliases` and `terminalNodes`, a group touching an AC rail grounds all of it, and a port/net name identifies the whole group rather than reporting an ambiguity.

Use `addNetLabel`, `renameNet`, and `renameNetLabel`; editor code must not assign `net.name` directly. Net-label text derives from the physical net name. Removing one label occurrence leaves the net and name intact. A provisional label on an unnamed net is committed atomically only after a non-empty name; otherwise it is discarded.

Unnamed `ground`, `supply`, and `vcm` markers auto-name an otherwise unnamed attached net (`VSS`, `VDD`, or `VCM`) and are treated as a shared AC-reference group by symbolic analysis. An owned marker label makes that marker local; double-clicking one creates its editable owned label. Deleting that label undoes it (`Circuit#removeLabel` → `_clearReferenceMarkerName`): the marker's value is cleared so no orphaned legacy value text is drawn, and its net returns to the global rail name unless another local marker or a net label still carries the local one. Renaming a marker-attached net away from its global name persists the same owned child label. Existing marker values remain display text unless committed as an owned label. Existing explicit net names are preserved when a global marker is attached. The historical `GND` ground name remains a compatibility alias for an unnamed ground marker. The web net list shows each unnamed VSS/VDD/VCM reference group once; selecting its row selects all physical members.

Small-signal analysis resolves the selected input, output, reference, AC-ground nets, and device regions, then builds one exact full-RLC small-signal model. It stamps one modified nodal analysis (MNA) system for `Z_{in}(s)`, `Z_{out}(s)`, and `A_v(s)`. `topological-solve.js` removes the imposed input voltage, solves strongly coupled blocks in dependency order, and recursively Schur-combines independent active branches at voltage articulation points. Both excitations travel through each block together; the input-source current is recovered from its KCL row. Feedback and reciprocal loading remain coupled; singular open-port decompositions fall back to the coupled solve. Numeric callers retain the combined solver; `topologicalSolve:false` exposes that reference path for symbolic comparisons. Algebraically uncoupled subcircuits are excluded without dropping controlled-source dependencies. Independent DC current sources are open circuits, independent DC voltage sources are shorts, and all DC power/reference rails share AC ground.

Before that solve, `pipeline.js` runs the coupled primitive graph through `reduce.js`'s `reduceNetwork`: a general textbook series/parallel pre-reduction that merges every group of parallel edges (never eliminating a node any controlled source's terminal or control touches, or either query node) into one equivalent admittance, recording each merge as a proof. `engine.js` (`buildParallelEquivalenceProofs`) turns each proof into up to four `present.js` equivalences — the exact branch impedances as solved, those same branches independently reduced under whichever assumptions are selected (e.g. `g_m r_o ≫ 1`) and recombined, and the `s→0` limit of each (dropping any branch that's an open circuit at DC, e.g. a capacitor, rather than trying to combine an infinite impedance in parallel) — because the textbook default equation and the separate DC-limit equation are each built by one leading-term/`s=0` reduction of the *whole* expression, which does not by itself preserve this factored structure. `equivalenceTable`'s result is a table `render` checks at every recursive call, not just the top-level value, so `\|` notation can surface deep inside a bigger `Z_{in}`/`Z_{out}`/`A_v` expression — e.g. every branch meeting at a common-source output node (`R_D`, `r_{o1}`, a load cap, a Miller shunt) rendering as one flat `A \| B \| C \| D`, on the default equation actually shown/annotated, not just an internal exact-only row. Deliberately parallel-only in `reduceNetwork` itself: series-merging a reactive element hands Bareiss elimination a pre-divided, `s`-dependent admittance where it previously saw only simple (denominator-1) entries, which defeats Bareiss's fraction-free efficiency and can cost more solver budget than the smaller matrix saves — confirmed by a regression on `rlc-second-order`. Series combinations still display correctly on their own via plain addition; they just aren't pre-collapsed.

The GUI never calls `analyzeSmallSignalV2` directly — `web/main.js` always wraps it in `report-adapter.js`'s `adaptCombinedReport`, which re-renders `equation`/`exactEquation` (and the DC-limit rows) from the raw expression through its own `render()` call rather than reusing engine.js's already-rendered strings. Both `equivalence` and `equivalences` must therefore be read off the v2 response (`source.equivalence`/`source.equivalences`, via `equivalenceOptions()`) and passed into every one of the adapter's own `equation(...)` calls; missing this on any of them (the AC row, the DC row, or a later addition) silently drops `\|` for that row alone while leaving `analyzeSmallSignalV2`'s own return value looking correct — check with `adaptCombinedReport(analyzeSmallSignalV2(...))` end to end, not engine.js's return value alone. Analysis rows render through `render.js`'s shared `texToMathML`, the same parser used by schematic annotations; wide equations scroll within their own row.

Each displayed row also carries a provenance render, which is what makes a term in an equation clickable. `present.js` `renderExpressionWithProvenance` wraps every sub-expression in a `\pv{n}{…}` marker that `texToMathML` turns into one `<mrow data-node="n">`, and `stripProvenanceMarkers` recovers the ordinary TeX. Markers are opt-in, so nothing persisted, exported, or edited as a label ever contains one. `test/analysis-provenance-v2.test.js` asserts over the whole golden corpus that a provenance render differs from an ordinary one by markers alone and that its MathML is identical once the wrapper rows are removed — measured in Chromium as zero width and height change. Two things must keep reaching through a wrapper or that breaks: the two renderers that post-process a child's rendered text (stripping a leading minus in the proven-product branch, comparing a denominator to `1`) use `mapMarked`/`markedBody`, and `mathMlNucleus` unwraps before deciding whether a nucleus is a single character, so TeX's Appendix G rule 18a `mpadded` still lands on the glyph rather than on the group. `report-adapter.js` builds `equationProvenance` beside each `equation` string, for the same reason `equivalenceOptions` must reach every row: a row rendered anywhere else would have to reproduce the label, approximation flag, and equivalence options, and any mistake fails silently on that row alone. `provenance.js` inverts `devices.js`'s `parameterName` chokepoint into `symbolProvenance` (raw symbol name such as `gm1` — not its rendered `g_{m1}` — to `{component, role, kind, primitives}`), exposed on the v2 report. It takes several primitive lists, earlier winning, and the engine passes the solved set and then the conversion set: a symbol can outlive its own primitive and still appear in an equation, both for a Miller-absorbed feedback capacitor (the shunt admittances carry `C_{GD}` in their expressions while the capacitor's primitive is gone) and for an `r_o` the engine had to keep after `r_o -> infinity` already filtered it out. An unresolved symbol does not fail — it silently stops highlighting — so `analysis-provenance-v2.test.js` asserts that every symbol of every displayed row resolves, over the corpus and over a Miller common-source fixture the corpus does not contain. A Poles or Zeros row is several root equations shown together, each rendered on its own, so `joinProvenanceRenders` renumbers their markers before joining with the same separator the displayed string uses; without that the second root's node ids would collide with the first's and highlight the wrong devices. The joined render is kept only when every root has one. `main.js` decorates each `[data-node]` with `data-components`; hovering a term traces those components through `editorOverlay`'s `emphasis` option (`componentShapeSvg`, restyled by `.equation-emphasis`), clicking locks the highlight, and clicking the locked term again widens to the enclosing sub-expression. The highlight belongs to the dock: rebuilding the rows and `closeAnalysisDock` both clear it.

Math is set in Latin Modern Math, vendored as `src/web/fonts/latinmodern-math.woff2` (GUST Font License; see that folder's README for provenance) and loaded by an `@font-face` at the top of `style.css`. It is Computer Modern carrying an OpenType `MATH` table, which is what makes Chromium lay MathML out with TeX metrics; no system ships it, so without the vendored copy the stack falls back to a Times clone with no math metrics and equations stop looking like LaTeX. `texToMathML` follows TeX's own typesetting rules for the rest: a fenced group is its own `<mrow>` so its delimiters size to that group alone (`\left…\right`, not the tallest thing on the line), a fence stretches only around genuinely tall content because a stretched glyph is also padded away from its content, a leading sign is the tight prefix form and every sign is drawn as U+2212, `\pi`/`\Delta`-style Greek renders as letters (lowercase italic, uppercase upright), and a single-character script nucleus is wrapped in `<mpadded depth="0">`/`<mpadded height="0">` (`mathMlNucleus`) so scripts ignore that character's own metrics — TeX's Appendix G rule 18a. Without it MathML drops a subscript clear of a descender via the MATH table's SubscriptBaselineDropMin, setting `g_{m1}` 0.17 em lower than `r_{o1}`; mpadded changes only the reported box, so the glyph and the measured label footprint are untouched. Exports and clipboard images embed the face: `drawing-export.js` `withEmbeddedMathFont` inlines it as a data URI when the drawing carries math, since a standalone SVG, the PNG rasterized from it, and the server's PDF print page all leave this stylesheet behind — which is why that print page's CSP allows `font-src data:`. The `svg` console command does not embed it.

Separately, `graph.js`'s `splitAtNode` identifies parallel input/output branches, including direct shunts and active loads. Output-impedance topology treats the zeroed input as AC ground. Independent branch solves record parallel identities without replacing the raw exact port queries. `topology.js` finds internal unilateral signal cuts that dominate the output, derives each stage's signed short-circuit transadmittance on its own coupled block, and displays gain as transadmittance times loaded output impedance; a cascade retains the product of these stage gains. Selected assumptions act on each stage and physical load branch before recombination. `present.js` carries these proven product/parallel identities through the GUI adapter and DC limits. Optional presentation work has separate bounded budgets; `topologicalPresentation:false` retains ordinary algebraic presentation. See `docs/topological-small-signal.md`.

DC results are the `s → 0` limits of the canceled full-RLC expressions: capacitors become open circuits and inductors become shorts. AC rows appear only when `s` remains in the final expression. Poles and zeros come from the canceled denominator and numerator and are indexed from zero. The block-wise solve can leave a common polynomial factor in `s` spread through expanded sums, so `polynomial-gcd.js` (a modular screen, then a bounded exact multivariate GCD) cancels it before pole/zero extraction and before the dominant-pole truncation; displayed response expressions keep their factored form. Each first-order pole/zero location then gets the selected post-solve assumptions applied as its own quantity, listed like any other assumption. Root extraction (`response.js`): roots at the origin are split off first, first-order roots are cancelled fractions, and second-order roots use the monic quadratic formula, collapsing to exact roots when the discriminant is a monomial perfect square. One shared operation budget covers a whole analysis and any value it produced marks it exhausted, so a *structural* outcome must never be reported as one: `rational.js` `rationalFunction` keeps the uncancelled coefficients when a content factor does not divide every coefficient exactly, instead of failing the report as over budget (a cascode-compensated two-stage amplifier used to die there in a second, whatever `maxOperations` said). Exact equations, MNA details, and the full read-only small-signal netlist remain available for inspection.

A three-terminal NMOS has its implicit bulk tied to VSS; a three-terminal PMOS has it tied to VDD. These rails are AC ground. Four-terminal MOS devices use their actual bulk net. Ignoring body effect means substituting `g_{mb}=0`; it never reconnects the bulk. The only device-region override is triode.

A resistor's small-signal attribute "treat as R = ∞" (`Circuit#setComponentAnalysis`, `component.analysis.resistance === 'infinite'`) drops its branch from the primitive set entirely — an open circuit, not a primitive carrying an infinite value — read directly off the live `Circuit` by `devices.js`, the same pattern MOS triode overrides already use.

A saturation-region MOS device's output branch is stamped as a `resistor`-kind primitive with symbolic value `r_{o,n}` (`devices.js`), not a conductance. `r_o -> infinity` is a pre-solve open circuit: `pipeline.js` leaves the selected devices' `.ro` primitives out and lists `r_o -> infinity (Mn)`; only when that makes the solve singular (e.g. an inverter output driven only by current sources) does the engine keep `r_o`, apply the post-solve leading-term limit, and say so in the log. The engine accepts both the GUI's canonical option names (`neglectBodyEffect`, `highIntrinsicGain`, `neglectChannelLengthModulation`, globally and per device) and the engine aliases. Default `g_m r_o ≫ 1` instead removes an additive term only when another term exceeds it by a product of the selected devices' `g_m r_o` pairs, including cross-device products such as a cascode's `g_{m2} r_{o1}` (the textbook approximation assumes comparable device output-resistance scales); it never implicitly declares `g_m R_S ≫ 1` or a cascode branch impedance much larger than an unrelated `R_D`. Explicit custom scaling retains the formal leading-term path. A reduction is rejected outright when it loses a power of `s` (`approximation.js` `retainsFrequencyPowers`): dropping subleading terms inside a difference can annihilate one whole coefficient, and the result would claim a pole or zero at the origin the circuit does not have -- the exact expression is kept for that quantity while the poles and zeros still simplify. The triode-region channel resistance remains its distinct symbol, `r_{ds,n}`.

The canonical presentation options are: ignore body effect (`g_{mb}=0`, on by default), assume high intrinsic gain (`g_m r_o ≫ 1`, on by default), ignore channel-length modulation (`r_o → ∞`, off by default, applied before the solve as above), and dominant-pole approximation (off by default). The other assumptions are applied only after the exact solve, and only assumptions that change the displayed result are listed. Presentation flattens small resistive branch sums and places each transistor’s `g_m r_o` factors together, minimizing nested parentheses while preserving proven gain/load and parallel identities. Presentation composes nested quotients, reciprocal sums, and reciprocal powers into one fraction while treating proven parallel impedances as indivisible factors; pole/zero multiplying factors belong in the numerator rather than following a standalone reciprocal. This is exact display algebra, separate from the assumptions. Exact algebraic cleanup always cancels proven common factors, combines repeated powers, normalizes signs, orders powers of `s` from highest to lowest, and removes redundant parentheses.

The Miller approximation (`src/core/analysis/miller.js`) is a fifth listed assumption ("Miller approximation (M1)"), but unlike the four above it is a pre-solve modeling transform, not post-solve cleanup — on by default, opt out with `millerApproximation: false`. It detects any series/parallel R/L/C feedback network bridging a gm branch's own gate and drain (reduced to one equivalent impedance `Z_fb` by `src/core/analysis/reduce.js`'s general two-terminal series/parallel reducer — series-merge a private degree-2 node, parallel-merge coincident edges, fixed point; a bridge/lattice sub-network that needs a star-mesh transform is left untouched), solves the stage's own DC gain `A_v` across that bridge with it removed, and, only when the feedback network opens at DC, replaces it with two decoupled shunt admittances `(1-A_v)/Z_fb` at the gate and `(1-1/A_v)/Z_fb` at the drain before anything reaches `buildMNA`. Feedback networks that conduct at DC (a resistor or parallel RC bridge, for example) remain in the exact MNA model: bridge-open gain does not capture their loading or feedthrough. Their input-impedance relations are rendered through algebraically verified Miller identities instead. Miller shunts are supported `Y` entries in the read-only netlist, with unique input/output IDs and the original feedback components, impedance, and bridge-open stage gain recorded in notes. Applied Miller approximations appear in the schematic assumptions block. A bridge whose internal node is also used elsewhere (another device's terminal or control) is left alone rather than guessed at.

The GUI report order is `Z_{in}(s)`, `Z_{in}(0)`, `Z_{out}(s)`, `Z_{out}(0)`, `A_v(s)`, `A_v(0)`, poles, zeros, then assumptions; rows without additional information are omitted. **Annotate schematic** places the displayed equations below the figure, aligned with its left edge and separated by two grid cells. AC equations, poles, and zeros are annotated only when reactive terms remain. Successful reports use Equations, Log, and Small-signal netlist tabs.

Analyze opens a non-modal dock (`#analysis-dialog.analysis-dock`) between the canvas and side panel; the toolbar button toggles it and carries `aria-pressed` while it is open, so it reads active like the view toggles, its left edge resizes it (`mosfeteer:analysis-width`), and below 760 px it overlays the canvas. Editor hotkeys keep working while it is open; Escape inside the dock closes it. Node select options show the markup-free net name plus physical id (`VIN — N15`, via `analysis-state.js` `analysisNetOptionText`), since native options cannot render subscripts. Each node select has a crosshair Pick button: the next canvas click on a wire or connected pin sets that net (Escape cancels, status shows PICK NET). The selects refresh on model edits, and a notice marks results derived before the latest edit; after Derive the result scrolls into view. The Analysis form persists per named schematic across close/reopen and reload. Saved component and net references are filtered against the current model. Fresh defaults choose a marked role, then a selected net/component hint, then output/input port nets (preferring the non-inverting `…P`/`+` input), then `VOUT`/`VIN`-style names; with several input ports the unused ones are added to AC grounds, and changing the input swaps them. Input, output, and AC-ground roles can prefill the form; device settings use the same canonical option semantics. Multi-selection context actions apply atomically to compatible selected objects.

Editor `L` starts persistent electrical net-label placement. A click must land on one unambiguous physical wire; at a crossing, one selected/highlighted net must identify the target or placement is rejected. Named nets add another label occurrence. Unnamed nets open the provisional inline edit described above. `Shift+N` places one free annotation, `a` places a multi-point arrow (click the start and any intermediate/end vertices, then press Enter), and `b` places one box. `l` remains active for multi-point line placement until Escape. Editing a net label renames its physical net; editing an annotation or owned label changes only that label. Naming a port or net to match an existing port/net opens a virtual-connection confirmation; declining leaves the name field open for correction.

`LabelInstance` fields: `id`, `text`, `align` (`center|left|right`), `owner` (`refdes|null`), local grid-snapped `offset` for owned labels, world grid-snapped `anchor`, and net-label `netSide` (`above|below|left|right`). Visual line and arrow annotations store snapped multi-point `points`; they are not wires or nets and support vertex/segment editing. Lines render with rounded caps, while arrows put the head on the final segment and position their child label from the first authored segment.

Label bboxes use tight per-glyph widths (`LABEL_FONT_SIZE=38`, matching rendered `INSTANCE_FONT` / `LABEL_FONT`; `LABEL_CHAR_W=8` at font 12 for the bold/italic label face; narrow/default/wide buckets) and `LABEL_CAP_H=round(38*0.7)=27`. Rendering expands the tight box to even grid-cell multiples in both dimensions (`colWidth()` / `rowHeight()`), minimum two cells. Free and owned labels center on their anchors, so re-measuring a label moves both its edges by half the change. A left- or right-aligned free annotation therefore keeps its aligned edge instead: `syncRenderedLabelMetrics` shifts the anchor by `interaction.js` `alignedAnchorShift` whenever a measurement resizes the box. Analysis annotations are placed flush with the figure's left edge and that intent lives only in the runtime `equationAnnotationLayout`, so without this a metrics change (a new math font, new browser metrics) slides a saved equation stack sideways on the next open; the correction is one-time per document and marks it dirty. `clearMeasuredTextBounds()` drops only the runtime measurement and keeps the persisted `mathBox` as that reference, unlike `clearRenderedTextBounds()`, which a text edit uses to drop both. Net labels keep the electrical anchor on the wire and put one box edge on it: `above` for horizontal paths and `left` for vertical paths. `setText` always updates the box. `textPos()` returns the `<text>` `{x,y,anchor}`, horizontally aligned inside the box and vertically centered; left/right text sits `LABEL_ALIGN_INSET` (a quarter cell) inside its box edge, clamped by `alignInset()` so it never crosses the far edge, and alignment never resizes the box. Math labels apply the same side padding.

MathML measurement unions the intrinsic rectangles of individual math lines (never the full-width multiline containers) and converts foreignObject padding to screen units. Browser-measured sizes use a 0.001-world-unit rounding tolerance at grid boundaries, keeping label edges and fraction centerlines stable across zoom and reload. A math label's size comes from the math font's own metrics and is measured once per text, so `syncRenderedLabelMetrics` skips math labels until `document.fonts` reports the face loaded (`mathFontReady`), then clears their runtime bounds so each measures again: measuring during the webfont's `font-display: block` period locks in a box roughly half the right height, and the foreignObject then clips the glyphs for the rest of the session. The `<math>` layout box itself is an exact pixel boundary once the face is loaded — verified against painted pixels — so nothing else needs padding. Math labels persist their measured even-grid footprint as `mathBox:{w,h}` (tight browser glyph metrics remain runtime-only), preventing an estimated box from shifting aligned text on the first frame after loading; text changes clear that footprint. Math labels render through the live MathML-backed SVG `foreignObject` at normal weight, and support explicit newline-separated lines for compact math annotations such as the analysis assumptions block. Analysis equation annotations are re-centered after browser measurement using a common pitch derived from the largest adjacent half-sum of bbox heights, so at least one neighboring pair can touch; the separate assumptions label does not affect that pitch and is omitted when no selected or simplification approximation applies. Its `r_o` summary lists device-specific omissions only when no global rule exists, suppresses same-direction per-device entries when a global rule exists, and collapses an equivalent all-device override in a multi-device model into the global statement; a lone device-specific setting remains visibly scoped.

Inline label editing supports `_{...}` and `^{...}` rendered as tspans. Ctrl+, and Ctrl+. wrap a selection as subscript/superscript; repeating the same operation unwraps it, and a mixed selection makes every touched group plain text. The pure helper is `model.js` `applyMarkup(text,s,e,mark)` and is unit-tested.

`addComponent` auto-creates an owned instance label (default numeric source such as `M_{1}`, centered) and keeps it synchronized with the unique component name. Every symbol uses `refPos:null` plus `labelOffset`; no id is drawn as legacy plain font-12 `refPos` text. `fromJSON` constructs components with `noLabel:true`, then loads `data.labels`, migrates legacy compact numeric labels to explicit markup, and drops orphaned owned labels. `nextRefdes(prefix)` returns the smallest unused positive index, reusing numbers after deletion.

Style controls and style paste recolor component owned labels and annotation child labels. Coloring a whole net also updates all per-segment wire color overrides.

Transforms are origin-anchored and pure: component origin never moves, repeated transforms remain stable and grid-aligned. In Virtuoso mode and ghosts, `r` rotates clockwise, `Shift+r` mirrors horizontally, and `Ctrl+r` mirrors vertically; `Ctrl+Shift+r` is unbound. CLI `rotate`/`mirror` use the same component transform. Set transforms use the exact selection midpoint, including half-grid midpoints, so odd-width sets mirror stably. Mirrors use world horizontal/vertical axes even after component rotation. Free labels are never orbited by transforms. Rotating a multi-component set rotates positions and individual orientations around the set midpoint.

Owned labels follow components. Net labels stay attached to drawable paths, switch above/below or left/right according to drag side, and keep their bbox edge on the wire; dragging projects attachment to the nearest drawable point. Free annotations and wire geometry move independently. Annotation defaults are calculated once: box labels center above the top edge with their bottom edge touching it; arrow labels attach a text-box corner to the arrow base according to arrow quadrant. Later movement is independent.

Selection is role-aware across components, owned labels, free annotations, net labels, and wire segments. `selLabels:Set` plus primary `selLabel` supports multi-label selection; Shift-clicking an annotation and its text label in either order preserves both. `setLabelSelection(ids,primary)` updates both; `setSelection` and Escape clear both. `editorOverlay` highlights every `selLabels`. A selected object/set also gets a distinct magenta dashed horizontal/vertical center guide with edge ticks, computed from the combined selection bounds; the guide is interaction-only and never becomes diagram geometry. Shift+ArrowLeft/Right cycles label alignment. Nudge with arrow keys moves wires with components by passing a `moved` map to `rerouteNet`; nets whose terminals all share a delta translate rigidly, like a drag. `dd`/Delete removes the selected role-aware set. Double-click opens an inline text editor; Enter/blur commits, Shift+Enter inserts a persisted line break, and Escape cancels. The palette has a label button.

Selecting a net from the side panel or double-clicking its wire selects its junction solder components too. A highlighted net draws a blue halo over its paths and an r13 ring plus dot over each junction solder; devices are not highlighted. `opts.nets` carries highlighted nets and `opts.netSolder` carries their solder points.

The nets list and wire highlighting identify the physical net targeted by wire repair. When two physical nets occupy coincident geometry, select/highlight exactly one of them before editing; the selected net is the target, so either coincident net can be deliberately repaired without merging the nets. For tied wire picks, an explicit `selectedNets` preference outranks `diagnosticSelection.nets`; the diagnostic preference applies only when it identifies exactly one tied candidate. Stale or non-candidate IDs are ignored, and original iteration order is the deterministic fallback. Cross-net positive-length collinear overlap remains an electrical violation and is never auto-merged. A shared name is the deliberate virtual connection between the physical nets, so naming a net to match an existing port or net asks for confirmation before establishing that convention; port identities stay unique, so the convention lives on nets and net labels.

## Virtuoso editor

Normal mode uses this vocabulary:

- `i` starts fuzzy placement. Type to filter components and labels; Enter or Tab picks the best match, then click or Enter places the ghost. Fuzzy ranking is prefix > substring > subsequence, with shorter matches first. `#insert-menu` shows the live query and filtered entries with cached symbol previews (`symbolPreviewSvg`); an unfiltered list flows into columns, and the highlighted entry carries the Enter hint. The menu is anchored where insert mode opened (a world point, so it holds still while the pointer moves) and takes pointer events: hovering an entry moves the same highlight the arrow keys move, in place, and clicking one arms its ghost exactly like Enter. All printable keys, including h/j/k/l, append to the query; there are no Vim movement bindings while a ghost is active. In the picker, ArrowUp/ArrowDown move the highlight through matches and ArrowLeft/ArrowRight jump between categories; Enter/Tab pick the highlighted entry, and typing resets the highlight to the best match. Once a ghost exists, arrow keys move the cursor. Holding Shift while moving a ghost locks it to the dominant horizontal or vertical cursor direction. Escape first drops a ghost back to search, then exits insert. A committed component insertion resolves coincident terminals and wire endpoints immediately, so placing a reference marker, port, or any other symbol directly on a terminal connects it just like a move.
- `w` is the only Wire command. It starts from a terminal, existing wire, or free grid point. Clicks on terminals commit immediately; other clicks add committed route points. The live preview autoroutes each leg from the source through those points to the cursor. Press Enter to commit at any nonterminal point, including an open-ended wire. F3 (or right-clicking the Wire tool button) toggles orthogonal/diagonal routing for new wires; in diagonal mode only legs between clicked points are drawn literally, and pin legs are auto-routed. There is no uppercase-W protected-wire editor mode.
- `m` arms connected move. Before a ghost exists, drag from empty space to box-select a complete set; click any member of a preselected component/label/net/wire set to start the same whole-set ghost, regardless of whether the hit is a component, label, annotation, or wire. A selected label confirms the whole mixed set rather than narrowing the drag. Moving any selected component, label, annotation, or wire segment carries or re-routes its electrical connectivity; the moving set and connected wires are faint ghosts until the destination commits. Holding Shift during an active move locks the displacement to the dominant horizontal or vertical cursor direction. `Shift+m` arms detached move with the same source-hit rule: selected wire islands split from their nets, move with the selected component set, and retain selected terminal connections; unselected islands remain floating. Wire can reconnect split ends.
- `c` starts repeated copy. Before a ghost exists, drag from empty space to box-select a complete set; when a set is already selected, clicking any of its members—including a label or wire—starts the same complete copy source rather than narrowing the selection. Owned labels include their component; copying a net label alone creates a floating label, while explicitly selected components/nets retain complete-net copy behavior. Move the ghost, then click or Enter to commit; each later click commits another copy at that cursor. Holding Shift while moving the ghost locks it to the dominant horizontal or vertical cursor direction. The clicked source point is the copy anchor, not the set bbox center. Relative geometry is preserved. Rotate/mirror before placement persist; each transform uses the current copy point and rebases the follow origin, so later motion is only pointer delta. Escape cancels the ghost and returns to copy-tool source selection.
- `x` runs Check; `Shift+x` saves without checking. The Design check panel has Clear; deleting an object clears stale report and focus.

Connected move/transform ghosts remain one atomic history entry. Insert ghosts use the same world-space transform semantics. Holding Shift during a drag or ghost movement constrains the displacement to the dominant horizontal or vertical cursor direction. Touching pins connect only at committed position, never during a drag. Component moves and managed/fixed/floating wire drags run against an immutable-before, disposable preview transaction: pointer motion updates only the clone, Escape/click-without-motion discards it without changing history or drafts, and mouseup/Enter publishes one validated model and one undo entry. Preview renders never advance the committed model revision; cancellation restores the original model object.

### Wire interaction

Terminal clicks have priority in Wire mode: `nearestTerminal` accepts a click within `max(GRID/2,12px/unit)`, even when a wire crosses the pin. Wire hits (`queryWireHitIndex`) rank by distance from the raw pointer and use the grid-snapped point only when the raw pointer is near no wire, so a diagonal next to a bend is pickable. A wire click selects its segment(s) and highlights them orange; Shift-click toggles `selectedWires` keys of the form `netId:branch:segment`, with `selectedWire` as primary. Dragging moves every selected run: same-orientation runs move as a group; other orientations stay put but selected. A single aligned segment between topology points is independently bounded; adjacent aligned segments move together only when both are selected. Ordinary straight pin-to-pin runs cannot drag unless explicitly bounded by topology (`moveWireRun` keeps direct pins fixed).

A wire-run drop that creates a new cross-net collinear overlap is rejected: the drag is cancelled with an error and the pre-drag document is restored (plain drags edit the live document, so the restore does not rely on a preview transaction). `dd`/Delete calls `Circuit#deleteWireSegments`; all cuts use one branch snapshot so indices do not shift, and remaining geometry splits into connected components. A click that does not move, or moves less than threshold, never mutates the net. `dragMoved()` requires both >6 px client movement and >`GRID/2` world movement. Escape calls `cancelDrag()` and restores every pre-drag polyline. History is pushed once on mouseup; undo/redo round-trips a committed drag. A plain wire click sets `drag=null` before returning, preventing a later mousemove from causing a sticky reroute.

Normal picking order is label → exact terminal → wire (`pickWire`) → component bbox → empty space. Wires render behind bodies by default, but remain selectable and draggable inside or along a component body.

Wire-mode construction starts with a terminal, empty-space point (`wire.source={x,y}`), or existing wire (`{x,y,netId}`). Clicks on terminals commit immediately; clicks elsewhere add route points. The preview autoroutes each leg from the source through committed points to the cursor, and Enter commits the resulting managed route at a free point or wire interior, so an endpoint need not be a terminal. Collinear points collapse where valid. Enter on wire interior merges nets: the junction is a mid-wire anchor in `net.junctions`, both target-wire halves are walked, and a solder dot is created. `rerouteNet` and `routeNet` walk all anchors (terminals and junctions). At a coincident cross-net span, selection/highlighting of one physical net is required to identify the wire being edited; the overlap itself does not create a junction.

During partial connected-set moves, outside wire bodies remain fixed and boundary legs re-anchor; branches wholly inside the moved set translate with same-delta endpoint terminals. Connected component moves, rotations, and mirrors reroute every touched net holistically from terminals plus environment (`rerouteNet`) rather than hand-carrying wire bodies. Detached moves split selected islands and leave unselected islands in place. If every terminal of a net rides a moved component by the same delta (including Ctrl+A drags), translate all branches, route, and junctions rigidly. A polyline whose endpoint terminals ride components with matching deltas also translates; differing deltas re-anchor both legs while retaining the authored body. `_pruneDanglingBranches` drops branches whose endpoints are neither terminals, junction anchors, nor points shared by at least two branches; intentionally detached floating islands are retained.

## Routing and connectivity invariants

`Circuit#connectCoincident()` joins terminals that land exactly together. It runs in `addComponent`, `moveComponent`, `setTransform`, and `fromJSON`; loading runs it after explicit nets with `_loading` guarding recursion. Dropping ground on a MOS source connects them. Moving either component apart retains the net and routes a wire between them.

Managed nets are reduced to a deterministic minimum spanning tree by `Circuit#_reduceNet` → `reduceBranches` in `wiring.js` when geometry is freshly created, explicitly edited, loaded, or intentionally re-routed. Topology growth through `wireTo`, `wirePointTo`, and `connect` normally appends one smart-routed branch and preserves every existing branch; a redundant no-waypoint `wirePointTo` within already-connected explicit topology is a no-op, while an explicit target path can connect separate branches without treating a crossing as a junction. Explicit wire edits and transform/reroute commands remain the user-controlled geometry changes. Vertices are terminals and T/cross junctions; each polyline run between vertices is an edge weighted by Manhattan length. Parallel/duplicate and cycle edges are removed only at those explicit repair boundaries, including collinear overlaps after splitting at overlap boundaries. Reducer overlap boundaries are not junctions. Managed same-net positive collinear overlaps are pruned when endpoint-coincident pieces reconnect after copy/move; cross-net positive overlaps remain violations and are never merged automatically.

`normalizePath` removes a collinear middle point only on a monotonic run. A reversal at a terminal or junction is a real vertex and is preserved; this prevents clone/fromJSON/render from dropping a terminal leg in a balanced three-way net. Joined managed nets store explicit `net.branches` (polylines) and `net.junctions` (mid-wire anchors); single route-null two-terminal nets may derive their route from `Net.points()`.

### Router behavior

For orthogonal managed routes, `smartRoute` adds candidates that escape one grid cell outward along each terminal's `dir` (`applyDir`) before bending. Thus gate→drain leaves the gate west and approaches the drain from north, outside the body. Escaped candidates are preferred even for aligned pins; two gates sharing a column use a gate-facing U in a one-cell-off channel instead of a body-hugging straight line. Facing escapes collapse to a straight wire. `Circuit._pinDir` and the command-layer `pinDir` prefer `t.dir`, falling back to bbox heuristics.

`hardSafe` keeps committed segments at least one grid cell from every component bbox, exempting valid pin-connected escape legs. The shared MOS gate-bus exception allows a managed segment through the strict interior of an NMOS/PMOS body, including bulk variants, only if at least two MOS gate terminals share that physical net, the segment touches the crossed device's gate pin, and it follows that gate axis. `hardSafe`, automatic move validation, and `evaluate().wireThroughBBoxes` use the same exception; it never permits source, drain, bulk, passive, supply, or unrelated-net body crossings. Boundary-hugging is legal.

The routing environment includes `labelRects` as soft obstacles: `labelScore` prefers a one-cell-clear channel when available but never blocks a route through a label. Solder dots are excluded. Net labels remain electrically anchored to a drawable path and put a bbox edge on it. Fresh layout uses `_netEnv(excludeNetId)` to include every other net's explicit branches as wires, so `rerouteNet`, `_layoutFresh`, and `Net.points()` never auto-create collinear overlap with another net; crossings remain legal. `crossNetOverlaps` reports existing cross-net collinear spans.

Two-point candidate scoring is lexicographic: `[bboxCrossings, overlap, wireCross, componentClearance, labelClearance, pinConform, turns, length]`. After safety and spacing, fewer visible bends win before route length. A* (`astar`) is the live `smartRoute` fallback, not dead code. Diagonal candidates are filtered according to route mode.

Three or more terminals use `steinerBranches`/`steinerRoute` through `autoRoute` for fresh layouts and explicit full-net reroutes. A topology-growth click does not invoke those whole-net optimizers: it previews a smart route and commits only the new branch. The exact rectilinear Steiner attempt uses Dreyfus–Wagner subset DP on coarse-grid cells in the terminals' padded bbox, under hard body clearance. Exact DP is admitted only for at most 10 terminals, at most 25,000 graph vertices, an estimated split/relax cost of 120 million, and at most 2,000,000 subset-state cells; cancellation is checked throughout graph construction, connectivity checks, and DP relaxation, with a bounded chain fallback. Edge cost is one cell plus pin-conformity penalties (`CONFORM_SIDE=30` for perpendicular escape; `CONFORM_OPP=8` for opposite direction) and label clearance (`LABEL_EPS`). The first cell from a pin follows its direction; for example, a differential-pair virtual-ground source escapes downward and the T lands below the pair row, never on the pin row. The DP minimizes total tree length. Nets outside the exact-work limits fall back to an MST-of-shortest-paths Steiner 2-approximation, so all fresh layouts remain routable.

## Design Check and compatibility

The right-side **Design check** panel retains the latest report until another Check, object deletion, or Clear. Categories: dangling/unconnected terminals; component, component–label, and label–label overlaps; wire drills through component bodies; managed diagonal segments; grid errors; and cross-net collinear wire overlaps. Each issue focuses its component or net and exposes a repair hint. The read-only `explain eval` command groups the same issues with plain-language causes and hints; `explain connect REF.TERM REF.TERM` returns a dry-run route, bends, length, and pin escapes without mutating the circuit. Normal selection clears diagnostic focus without discarding the report. Save writes the design without requiring a passing check.

There is one wire model in the app: managed nets whose **diagonal segments are protected individually**, not net-wide. `net.allowDiagonal` is derived from the drawn segments (`syncJunctionSolders` recomputes it), so joins never spread it. Diagonal-mode drafts (`diagonalDraftPath`, shared by `wireTo`/`wirePointTo` and the editor preview) keep legs between clicked points literal and auto-route any leg that starts or ends on a pin. On component moves, a pin's diagonal leg stretches with the pin when clear of bodies, otherwise stays put behind an orthogonal connector; orthogonal legs re-anchor normally. Dragging a diagonal segment (`Circuit#moveDiagonalSegment`, editor `diagonalseg` drag in normal and `m` modes) moves it rigidly, keeping its angle and length. The orthogonal wire on each side runs from the nearest fixed point (a pin, a junction, another branch's end, or another diagonal's end): a still-aligned leg stretches, otherwise it reroutes. An unsafe position keeps the last valid preview. Orthogonal run drags ignore selected diagonal segments. `loadDocument` converts legacy `routingMode:"fixed"` nets through `Circuit#convertFixedNets`, and the cross-coupling inference and `wireDirectTo` install managed literal paths. The fixed-path engine remains in the core (for `Circuit.fromJSON` callers and `wireDirectTo(..., { fixed: true })`), but the app never creates fixed nets.

### CLI → server → browser fast loop

The agent/CLI workflow is on hold but kept working. A CLI circuit name maps to `<workspace>/<name>.schematic.json`. `POST /api/circuits/<name>/cmd` accepts `{ "cmd":"<line>" }` or `{ "cmd":"line1\nline2\n..." }`. The server serializes each file's load/run/save transaction, atomically replaces the file when anything mutates, and returns `{ name, path, mutated, results, state }` with revision metadata in response headers. `GET /api/circuits/<name>` (read-only) and `GET /api/document?path=` expose the same revision as `ETag`/`X-Circuit-Revision` and honors conditional requests. The CLI (`src/cli/index.js`) is a thin HTTP client over the command and deterministic generation endpoints; the generation preview/commit contract is documented in [`docs/circuit-spec.md`](docs/circuit-spec.md). The browser has no natural-language generation tool.


`GET /api/active` returns `{active:"<name>"|"", path}` plus `X-Active-Revision` when the active circuit exists. The server tracks the active circuit in memory and persists it to `data/active.json`; every command POST sets it. `PUT`/`POST /api/active` sets it explicitly; `DELETE` clears it. `syncActiveCircuit` polls every 500 ms with one in-flight request at a time, pauses while the tab is hidden, and uses active revisions plus conditional circuit requests to skip unchanged data. It switches/auto-loads the active circuit on first open or change and still merges file updates for the loaded circuit. Saves invalidate in-flight sync results so an older response cannot overwrite a just-saved design. A valid named browser draft restored on reload wins the first active poll, so the currently edited schematic is not replaced by stale server-active state; later active changes still load normally. The server sends `X-Active-Revision` only when the active circuit's file exists; while it is missing (not yet written, or deleted) the client waits silently without requesting the circuit, and loads it once the file appears. A missing document returns 404 naming only the file name. Users do not need to type a circuit name or pick it from the document list.

Debug hooks: `window.__commitFeedbackLog` (see commit feedback), `window.__circuit()` returns `{comps,nets,labels}`, with label `world` anchors; `window.__run(cmd)` runs one command on the visible circuit; `window.__load(state)` replaces the visible circuit from JSON. The demo circuit is gone (`src/core/templates.js`, `demo`, and `#btn-demo` were removed); command report/SVG tests use an inline `smallCircuit()`.

The server sends `Cache-Control: no-store`; `index.html` references `main.js?v=25`. `data/` and `node_modules/` are gitignored; `data/settings.json` holds the workspace and recent files and `data/active.json` the active CLI circuit. Server tests use `test/helpers/server.js`, which runs `src/server/serve.js` with a temporary `SCHEMATIC_WORKSPACE` and `DATA_ROOT`. `npm run serve` runs `src/server/serve.js` in Node watch mode (env `HOST`, `PORT`, `DATA_ROOT`, `SCHEMATIC_WORKSPACE`), so imported source changes—including the symbol registry—restart it automatically. `npm start` (`launch.mjs`) and direct `node src/server/serve.js` are fixed processes and must be restarted after source changes.

## Generated placement

Phase 2's pure analog placement seam is `src/core/placement.js` (`placeCircuit` /
`tryPlaceCircuit`), documented in `docs/circuit-spec.md`. It consumes normalized
topology, uses `ComponentInstance` world geometry, and returns component
placements plus declared ports, rail metadata, reserved corridors, and a
bounded deterministic report; it does not mutate or route a `Circuit`.

Phase 3's pure batch-routing seam is `src/core/routing.js` (`routeCircuit` /
`tryRouteCircuit`). It materializes declared physical nets through the model's
public reroute machinery, preserves fixed/authored paths, retries a bounded set
of stable net orders, and returns a routed circuit plus structured metrics or an
atomic failure; equal net names never merge physical nets.
